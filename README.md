# tg_bins

Telegram BIN 查询机器人:HandyAPI 三账号 round-robin 轮询 + 本地开放数据集兜底,Docker Compose 一键部署。

## 一键部署

服务器上执行**一行命令**:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/a06342637/tg_bins/main/install.sh)
```

自动完成:检查 Docker → 克隆仓库 → 交互问答(Bot Token、管理员 id、HandyAPI 账号数与各账号 key、日志条数)→ 生成 `config.yaml` → `docker compose up -d --build` 启动。

> 不知道自己的 user id?先把 bot 跑起来给它发 `/id`。

## 功能

- **直接发数字查询**,无需任何命令:≥6 位取前 6 位;支持带空格/横线的完整卡号。
- 发送后先回「🔎 正在查询…」,查到结果后**更新同一条消息**显示。
- 结果**先英文、后中文**(卡组织 / 类型 / 等级 / 发卡行 / 国家 + 国旗)。
- **预付卡**:任何形式的预付卡,结果最下方追加**三遍**醒目警告。
- **三账号负载均衡**:round-robin 均摊月额度;某账号限流(约 10 次/分钟)自动切下一个并冷却;**三个全限流时用本地库兜底**,不中断。
- **本地库双查**:6 位查询会同时比对本地库,**核心字段(卡组织/类型/国家/预付)不一致时,两个结果都发出来**对比;HandyAPI 查不到时也用本地库。
- **4–5 位查询**:HandyAPI 不支持,走本地库。

## 权限分级

| 角色 | 来源 | 权限 |
|---|---|---|
| 超级管理员 | `admin_ids` 的**第一个** | 查询 + 更新/重启/日志/状态 + 增删授权用户 |
| 授权用户 | 其余 `admin_ids` + 超管动态添加 | **只能查询卡号** |
| 其他人 | — | **完全静默**(无任何回应) |

## 命令 / 按钮

- **所有人**:`/id` 获取自己的 user id
- **授权用户**:直接发数字查询;`/start` 显示欢迎
- **超级管理员**:`/start` 打开管理面板,**全部按钮操作**:
  - 🔄 更新 / ♻️ 重启
  - 👥 **用户**:按钮列表(每人一个按钮,点进详情可 ✏️ 改备注 / ❌ 删除)· ➕ 添加(发 user_id 或 @用户名,自动反查 id;查不到则提示未找到)
  - 📜 **历史**:操作日志(谁、何时、查了哪个 BIN、增删用户等),最近 `log_lines` 条
  - ⚙️ **设置**:日志保留天数(7 / 30 / 90 / 自定义),超期自动清理
  - ℹ️ 状态:各账号可用/限流情况 + 最近运行日志
  - 命令仍可用:`/adduser <id|@用户名>` · `/deluser <id>` · `/users`
  - 超管直接发 `@用户名` 可反查 user_id。配置了 `telegram.api_id/api_hash`(在 [my.telegram.org](https://my.telegram.org) → API development tools 免费申请)时走 MTProto,可查**任意公开用户名**;未配置时只能查到和本 bot 交互过的用户。查不到会提示未找到。
  - 授权用户、操作历史、设置都存 SQLite(`data/tg_bins.db`),重启后仍在。

## 配置(后期修改)

所有交互项都写在 **`config.yaml`**,随时可直接编辑,改完点机器人里『♻️ 重启』(或 `docker compose restart`)即生效。字段见 [`config.example.yaml`](config.example.yaml)。

## 管理按钮说明

- **重启**:进程退出,由 `restart: unless-stopped` 自动拉起(几秒恢复)。
- **更新**:点后先 `git fetch` 比对版本,显示「当前 vX → 最新 vY」并让你**确认更新 / 取消**;确认后才 `git pull` 并自动重启,**重启完成会主动给你发一条「更新完成 + 版本」消息**。若本次改了 `requirements.txt`(依赖),会提示你在服务器执行 `docker compose up -d --build`;拉取失败则不会重启、直接报错。
- **历史**:操作日志存 SQLite,展示最近 `log_lines` 条;超过「设置」里的保留天数自动清理(启动时 + 每 6 小时惰性清理一次)。
- **状态**:各 HandyAPI 账号可用/限流情况,附最近几条运行日志(完整运行日志用 `docker compose logs -f`)。

## 注意事项

- **本仓库是公开的:切勿提交 `config.yaml`**(已在 `.gitignore`)。密钥只留在服务器本地。
- HandyAPI 免费版:约 **3000–5000 次/月、10 次/分钟**,多账号轮询叠加额度。
- **本地 BIN 库** `data/bin-list-data.csv`(约 37 万条开放数据)用于 4–5 位查询、限流兜底与双查对比,完全离线,可自行替换更新。
- 动态授权用户存 **SQLite** `data/tg_bins.db`,随挂载目录持久化。
